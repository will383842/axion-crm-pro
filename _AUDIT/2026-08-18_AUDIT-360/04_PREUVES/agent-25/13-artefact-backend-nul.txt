=== CE QUE C'EST ===
  taille   1835 octets
  contenu  la page d'accueil Laravel du produit (<title>Axion CRM Pro</title>)
  cause probable : une commande lancee depuis `backend/` avec une redirection
  Windows `> nul` (curl, artisan...). Sous cmd.exe `nul` est un PERIPHERIQUE ;
  sous Git Bash / MSYS c'est un NOM DE FICHIER ORDINAIRE. La redirection a donc
  cree un vrai fichier au lieu de jeter la sortie.

=== POURQUOI C'EST A NETTOYER, ET PAS SEULEMENT A RANGER ===
  git check-ignore -v backend/nul  ->  code 1  (NON ignore)
  => un `git add -A` le committerait.

  Or `nul` fait partie des noms de peripheriques RESERVES de Windows
  (CON, PRN, AUX, NUL, COM1..9, LPT1..9). Un depot qui contient un fichier
  nomme `nul` N'EST PAS CLONABLE / CHECKOUTABLE sous Windows.

  TEMOIN JOUE, depuis backend/ :
    cmd //c "type nul"   -> sortie VIDE (cmd lit le peripherique)
    wc -c backend/nul    -> 1835 (Git Bash lit le fichier)
  Les deux outils, sur le meme chemin, ne voient pas le meme objet.
  C'est exactement la famille du piege 1 du dossier (Windows / CRLF).

=== GESTE PROPOSE (je ne l'ai PAS fait : le fichier n'est pas le mien) ===

  et verifier qu'aucun `git add -A` ne l'a capture entre-temps.
