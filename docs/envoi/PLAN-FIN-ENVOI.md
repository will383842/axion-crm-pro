# Plan de fin du système d'envoi (palier 0 et suivants)

**Statut** : plan, aucun code. Rédigé depuis l'état de `main` au commit `954543d` (R19 fusionné).
**Pour qui** : les agents qui coderont chaque PR, et le relecteur. Le fondateur a demandé une réalisation de bout en bout, décisions prises selon les recommandations ; elles sont toutes listées en section 3.
**Règle absolue** : `ENVOI_REEL_ACTIF` reste `false` dans toutes les PR. Il n'y a ni domaine d'envoi acheté ni serveur d'envoi : aucune PR n'ouvre une connexion réseau vers un serveur de courrier, aucun test non plus. Le stop gagne toujours. L'anti-boucle site-sync n'est pas touchée (aucune PR n'écrit dans les tables ni dans les files de synchronisation du site), **sauf P1-LN-B** (l'import) : une adresse importée suit exactement le chemin R13 (`RegistreOppositionManuel::inscrire`, opposition sortante vers le site, anti-boucle `opt_out` intacte ; une adresse déjà venue du site n'émet aucun événement, une adresse nouvelle en émet un seul). Rien d'autre n'écrit vers le site.

## 2. Règles communes à toutes les PR

- Branche créée depuis `origin/main` au moment de commencer (jamais d'empilement). 250 à 400 lignes, tests compris. La description liste les fichiers autorisés (la liste fermée ci-dessous) et rien d'autre n'est touché. **Les lignes déplacées sans changement** (S0 : instantané éclaté par segment, entrées `NonServiAuPalier0` et `TROUS_REELS` recopiées) ne comptent pas dans la limite de 400 lignes : la PR colle la commande de recomposition (concaténation triée des `instantane-routes-envoi/*.json` = ancien fichier, à l'octet près une fois normalisé) et `git diff --stat` ; le reste du diff tient dans 400 lignes.
- **Tests rouges d'abord** : chaque test listé « rouge exigé » est écrit, lancé, vu rouge (sortie collée dans la PR), puis le code le rend vert.
- Aucun test affaibli, sauté ni supprimé. Un fichier de test **déplacé** (S0) garde ses assertions à l'identique ; la recopie ligne pour ligne se vérifie **une seule fois**, dans S0, par la commande collée dans la PR. `SocleFichiersCommunsTest` ne vérifie que ce qui reste vrai après les PR suivantes : les cinq sous-fournisseurs sont enregistrés dans l'ordre ; chacun des 19 couples R19 est soit dans un `trous/*.php`, soit une route réelle, soit une entrée `non-servis`, soit retiré du contrat par D1 ou D2 (jamais « sous-fournisseurs vides », « union des trous = les 19 » ni « union des instantanés = l'ancien fichier »).
- `CouvertureContratEnvoiTest`, l'agrégateur `NonServiAuPalier0` et `RoutesEnvoiInstantaneTest` lisent leurs dossiers par **`glob` (`*.php` ou `*.json`), triés** : ajouter un fichier de domaine ne modifie jamais l'agrégateur (qui ne serait plus partagé dans une vague).
- Un test existant dont seule la mise en place change (ex. construire la passerelle avec `FauxServeurEnvoi` dans le test) garde ses assertions identiques et porte dans la PR la ligne « Test modifié : pourquoi ».
- Les fonctions de base de données du plan : pas de clé étrangère vers `workspaces` (comme `envoi_journal_commandes`), `REVOKE EXECUTE … FROM PUBLIC` puis `GRANT EXECUTE` au seul rôle applicatif, et refus si `p_ws::text IS DISTINCT FROM NULLIF(current_setting('app.current_workspace_id', true), '')` (forme à `IS DISTINCT FROM` : sans contexte posé, `current_setting(…, true)` rend `NULL` et `<>` ne refuserait rien ; modèle : `envoi_injection_liberer`). **Seule exception** : `envoi_adaptateurs_reels_portes()` (S1-B, D11), qui ne prend pas d'espace, ne rend que des noms d'adaptateur (aucune donnée d'espace) et peut donc être appelée sans contexte. La variable de session n'est **jamais** une barrière. Le propriétaire des fonctions est SUPERUSER + BYPASSRLS : dans une fonction `SECURITY DEFINER` la RLS ne filtre rien, la fonction filtre donc **explicitement** `workspace_id = p_ws` (lecture, agrégation, suppression). La barrière des droits (absence de droit du rôle applicatif) ne vaut que si `CRM_DB_APP_ROLE_ENABLED=true` (faux par défaut, `.env.example`) ; tant qu'il est faux, seuls le déclencheur et la fonction protègent.
- **Interdit de basculer `ENVOI_REEL_ACTIF` avant la fusion de K17-AIG** (entre les vagues 3 et 4 la passerelle tourne encore sur le faux serveur ; sans effet tant que le drapeau reste faux).
- Migrations : **seulement dans S1-A, S1-B, S1-C, une par vague** (section 5), en ajouts seuls, `down()` réel ou inerte déclaré dans `NR17_RETOUR_INERTE_VOULU`.
- Chaque PR écrit son compte rendu `docs/envoi/lots/<ID>.md` (Fait, Reste, Risques, Tests lancés) : fichier propre à la PR, compté dans sa liste fermée.
- `cd backend && vendor/bin/pint --dirty`, PHPStan niveau 8, tests ciblés ; côté frontend `pnpm test` ciblé et `pnpm lint`.
- Aucun test ne touche le réseau : `Http::preventStrayRequests()`, résolveurs en mémoire (`ResolveurEnMemoire`, `LecteurBoiteMemoire`, `FabriqueLecteurFixe`), `FauxServeurEnvoi`.
- Noms interdits dans les routes (URI **et** nom de méthode de contrôleur) : `temoin`, `temoins`, `temoin-off`, `tout-arreter`, `reprendre`, `armer`. Une méthode de contrôleur s'appelle donc `reprise`, `arretGeneral`, `reactiver`, jamais `reprendre` ni `armer…`.
- Aucune route `GET /envoi/*` ne résout `ServeurEnvoi` (`AucuneRouteEnvoiNeResoutServeurEnvoiTest`) : les lectures lisent la base.
- Rien de privé : pas d'adresse, d'IP, de domaine ni de nom réels ; les exemples sont en `*.example.test`.
- **Audit Opus sécurité + données obligatoire** pour les PR marquées « Audit : oui » (section 6). Un audit est périmé dès que la tête de la PR change.

## 3. Décisions (prises selon la recommandation)

- **D1 — « Tout arrêter » et « Reprendre »** (`arretGeneral` lit `toutArreter($ws)` **avant** `armerToutArreter` : idempotence, une seule ligne de journal ; il émet l'alerte comme la commande) : le contrat change, pas les tests. `POST /envoi/tout-arreter` devient `POST /envoi/arret-general` ; `POST /envoi/reprendre` **sort du contrat**. Raisons : deux tests de garde interdisent ces mots dans les routes ; le runbook et `ToutArreter` exigent que la reprise reste une commande locale journalisée (`envoi:reprendre <espace> --auteur=`). L'arrêt, lui, va dans le sens sûr : il doit être à un clic. La route arme **seulement le drapeau de l'espace** (`DepotSocle::armerToutArreter`), sans `ServeurEnvoi::pause()` (cette pause est globale et toucherait les autres espaces) ; permission `users.manage` (propriétaire, administrateur ; opérateur et lecteur : 403 avec le message « demandez à un administrateur »). Idempotente : un second appel répond 200 sans nouvelle écriture ni nouvelle ligne de journal. À l'écran, le bouton « Reprendre les envois » est remplacé par un encart qui explique la commande locale et qui doit la lancer.
- **D2 — Notifications** : le contrat s'aligne sur la route réelle, `POST /notifications/{id}/read` (au lieu de `/lue`). Aucune route nouvelle.
- **D3 — Boîtes** : `GET /envoi/boites`, `GET /envoi/boites/{id}`, `POST /{id}/suspendre`, `POST /{id}/reactiver`, `PUT /{id}/reglages` sont servis. `POST /envoi/boites` et `POST /envoi/boites/test-connexion` répondent **501 `serveur_reel_requis`** : une boîte n'a de sens qu'avec un domaine acheté et un serveur, et ses secrets s'entreront par une commande locale masquée, comme `envoi:temoins-acces`. `reactiver` ne lève qu'une suspension **manuelle** ; une pause automatique répond 409 `pause_automatique` (seule `envoi:lever-pause` la lève). Aucun secret de boîte ne sort jamais d'une réponse. `PUT reglages` : bornes du contrat ; une limite peut descendre librement, monter seulement jusqu'au budget de chauffe du jour (422 au-delà).
- **D4 — `POST /envoi/sante/test`** : route servie, réponse **409 `envoi_ferme_palier_0`** (ce que dit déjà `pilotage.yaml` depuis R18), entrée dans `non-servis/sante.php`.
- **D5 — Chauffe** : `GET /envoi/chauffe` (lecture de `DepotChauffe`/`CourbeChauffe`) et `POST /envoi/chauffe/{id}/reculer` servis ; le recul va dans le sens sûr ; propriétaire seul (`workspaces.manage`), journalisé, idempotent pour la même journée.
- **D6 — Pause d'une séquence** : nouvelle table en ajout seul `envoi_sequences_gestes` (pause/reprise, auteur, motif, horodatage ; l'état est le dernier geste). Une séquence en pause est **sautée** par `Sequenceur::executer` (filtre dans la requête), elle ne consomme donc pas `REPORTS_MAX`. `reprise` répond 409 si l'arrêt général, une pause automatique ou un frein est actif ; une reprise ne lève jamais un frein. `pause` : `users.manage` ; `reprise` : `workspaces.manage` (contrat).
- **D7 — Plafond de 300 par jour et par espace** : butée **en base** en plus du code. Table `envoi_compteur_espace (workspace_id, jour, n)` — **pas de clé étrangère** vers `workspaces` (sinon `nettoyerEspaces()` de `PlafondConcurrenceTest`, qui fait `DELETE workspaces`, casserait) — et fonction `SECURITY DEFINER` `envoi_compteur_espace_reserver(p_ws, jour, plafond)`. Elle **refuse** si `p_ws::text IS DISTINCT FROM NULLIF(current_setting('app.current_workspace_id', true), '')` (donc aussi sans aucun contexte) et filtre **explicitement** `workspace_id = p_ws` (le propriétaire contourne la RLS : un autre espace ne peut pas consommer ces places). Si `LEAST(plafond, 300) < 1`, elle rend faux **sans rien écrire** (le premier `INSERT` donnerait sinon une place avec un plafond de 0) ; sinon elle incrémente en une instruction (`INSERT … ON CONFLICT DO UPDATE … WHERE n < LEAST(plafond, 300) RETURNING n`) et rend faux si la place n'existe pas. Droits : le rôle applicatif a **SELECT seul** sur la table (ni INSERT, ni UPDATE, ni DELETE, ni TRUNCATE) ; `REVOKE EXECUTE … FROM PUBLIC` puis `GRANT EXECUTE` au rôle applicatif ; seule la fonction écrit. **Libération** : `CREATE OR REPLACE FUNCTION envoi_injection_liberer` décrémente aussi `envoi_compteur_espace` pour `workspace_id = p_ws` et le `jour` de la réservation (`v_jour`, lu comme le fait déjà la fonction), jamais sous 0, une seule fois par réservation, sinon chaque réservation libérée brûlerait une place pour la journée. Les réservations antérieures à P1-PLAFOND n'ont compté aucune place d'espace (aucune n'existe en production) : le compte rendu de P1-PLAFOND le dit, et ajoute que `envoi_injection_liberer` décrémente aussi pour une réservation faite entre la fusion de S1-A et celle de P1-PLAFOND qui n'avait compté aucune place d'espace : le plancher à 0 empêche toute valeur négative, l'effet se limite à une place rendue à tort ce jour-là. Plafond effectif = `min(réglage R14 de l'espace, ENVOI_PLAFOND_JOUR, 300)`. **Appel** : `PasserelleLocale` ignorait la valeur rendue par `reserverInjection` ; la butée est appelée **avant** l'INSERT du journal, seulement pour une clé nouvelle ; un refus de la butée rend `ResultatInjection::reporte(+1 jour)` **à l'intérieur de la fermeture** de `sousVerrouInjection`, sans jamais lever hors de la transaction (une exception annulerait aussi les `perimerReservations` de la même transaction et leurs alertes) ; aucune ligne de journal ni de compteur global ne reste. `noterInjection` n'appelle **pas** la butée (pas de double comptage). Pas de `CHECK (n <= 300)` figé dans la table : le relever un jour exigerait un `DROP CONSTRAINT`, interdit ; la borne vit dans la fonction (`CREATE OR REPLACE`). Le plafond global reste celui du code et de `envoi_compteur_global`.
- **D8 — Listes de refus** : pas de nouvelle liste ; on **réutilise le registre R13** (portées adresse, domaine, SIREN). Import réservé au propriétaire, CSV d'une colonne (adresse ou domaine), 5 000 lignes et 1 Mo au plus, en **deux temps** obligatoires : simulation (compte des lignes valides, déjà présentes et refusées, par numéro de ligne, sans jamais renvoyer une adresse), puis confirmation qui porte l'empreinte SHA-256 du fichier simulé. **Format fixé (contrat S2-CONTRATS)** : `POST /envoi/opposition/import` reçoit un corps `application/json` `{etape: simulation|confirmation, contenu: <texte CSV, 1 048 576 octets au plus>, jeton?: <jeton de simulation>}`. **Jamais de `multipart/form-data`** (PHP écrirait lui-même le fichier reçu dans `upload_tmp_dir` avant tout code de l'application, et `UploadedFile::fake()` crée un fichier temporaire : la garantie « jamais sur disque » serait intestable). L'écran lit le fichier dans le navigateur (`File.text()`) et envoie le texte. Le texte est renvoyé à la confirmation et le serveur **recalcule son SHA-256** avant de le comparer au jeton. Le serveur garde la simulation : elle pose un **jeton à durée courte** (cache, clé utilisateur + empreinte, 15 min, sans adresse) ; une confirmation sans jeton valide ⇒ 409. Les lignes importées gardent `source = 'manuel'` et portent `import_id` (colonne ajoutée). **Chemin R13 intégral** : une adresse importée passe par `RegistreOppositionManuel::inscrire` (donc `email_suppressions`, `opt_out` et `OppositionSortante` → événement sortant vers le site) ; c'est l'exception P1-LN-B de l'en-tête. Une adresse déjà venue du site n'émet aucun événement ; une adresse nouvelle en émet un seul. ## 8. M3 — Séparation par client et licence : après le premier envoi

**Décision D17 : M3 n'est pas nécessaire avant le premier envoi.** Raisons :
1. Le premier envoi est celui d'**un seul client** (Axion). Les données sont déjà cloisonnées par espace : RLS forcée sur chaque table `envoi_*`, `WorkspaceContext`, produit `envoi` activé par espace (`produit-envoi`, 404 sinon), plafond par espace, arrêt général par espace.
2. Les parties **partagées** (pause globale du serveur, compteur global, réputation commune des IP et des domaines, relève IMAP) ne posent problème que lorsqu'**au moins deux** clients envoient : un client pourrait alors user le plafond global ou la réputation de l'autre.
3. La licence est une question commerciale et contractuelle (facturation, droit d'usage), sans effet sur la sûreté de l'envoi.

**M3 devient obligatoire avant que le deuxième client envoie son premier message.** Découpage proposé (même règles : branches depuis `main`, petites PR, migrations en ajouts seuls réservées le moment venu) :
- **M3-1 Client** : table `clients` (ajout seul), lien espace → client, aucun changement de comportement.
- **M3-2 Ressources par client** : domaines, IP et boîtes rattachés à un client ; refus d'envoyer depuis la ressource d'un autre client (garde dans l'aiguilleur K17).
- **M3-3 Plafond par client** : butée en base par client, à côté de celle par espace ; la somme des plafonds clients ne dépasse jamais le plafond global.
- **M3-4 Pause par client** : « Tout arrêter » et les freins s'appliquent au pool du client, plus jamais au serveur entier.
- **M3-5 Licence** : droits d'usage du produit Envoi par client (période, volume), lus par `produit-envoi` ; expiration = arrêt, jamais suppression de données.
- **M3-6 Écrans** : vue « clients » de la console, en lecture d'abord.

## 9. Ce que ce plan ne fait pas (et ne doit jamais faire)

- Il n'active pas l'envoi réel : `ENVOI_REEL_ACTIF` reste `false` partout ; aucune PR n'ajoute une route, une commande ou un réglage qui le change.
- Il n'achète rien (domaines, serveur, comptes des témoins) : ces achats et le premier envoi réel restent des gestes humains du fondateur, après le feu vert accordé.
- Il ne supprime aucune personne ni aucune opposition. La seule suppression prévue porte sur des lignes **techniques** de `envoi_tentatives` de plus de 400 jours, après agrégation (D16).
- Il ne fournit pas le signal K17 qui rend prouvables les points `serveur_reel` du feu vert : tant qu'il manque, « accorde » est impossible partout (voulu) ; ce sera une PR ultérieure, avec audit (D12).
- Il ne règle pas la sortie du mode témoins : `auto.mode_temoins_vrai` et `auto.signature_absente` (vrais seulement tant que c'est fermé) rendent l'adaptateur réel inatteignable ; à revoir dans la PR qui sortira du mode témoins (D11, D12).
- Il ne garantit pas que « Tout arrêter » atteigne Kumo porte fermée : `PasserelleLocale::pause()` ne transmet rien tant que `ENVOI_REEL_ACTIF=false` (aucune connexion réseau). Couper le drapeau ne vide pas une file déjà chez Kumo ; « Tout arrêter » d'abord, drapeau ensuite (D11).
- Hors contexte d'espace, l'aiguilleur ne lit jamais les relevés d'événements de Kumo (`lireEvenements` ne répond rien) ; à reprendre avant le premier envoi réel, quand un appelant de `lireEvenements` existera (D11).
- Il ne touche pas l'anti-boucle site-sync (seule exception : P1-LN-B, l'import, qui suit le chemin R13, voir l'en-tête).
- `envoi:sante` appelle `sante()` hors contexte d'espace : `ok = false`, aucun battement noté (D11) ; le sens sûr est alors la pause des files 15 minutes après l'ouverture de la porte ; à reprendre avant le premier envoi réel.
- `envoi:reprendre` ne lève pas la pause chez Kumo (hors contexte, l'aiguilleur répond comme le faux serveur) : une file mise en pause par « Tout arrêter » y reste en pause après la reprise locale ; à reprendre avant le premier envoi réel, avec le runbook.
