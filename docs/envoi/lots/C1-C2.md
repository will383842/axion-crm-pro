# Lot C1-C2 — rattachement automatique de la personne née d'une demande (partie C1)

Suivi : #784, commentaire « PLAN C1-C2 ». Cette PR est la PR-1 du plan : **C1 seulement**. C2 (`SiteSyncIngestService`) vient dans une seconde PR, créée depuis `main` après la fusion de celle-ci.

## Comportement
- Quand le dossier client de la console arrive avec un contact portant une `person_key`, le CRM lie la personne née d'une demande sans SIREN à ce contact, puis rattache à la fiche ses demandes en attente (même clé).
- `pending_match` est gardé sur la demande (historique) ; `payload.arbitrage.attached_by = 'automatique:dossier_client'`.
- Rien n'est déplacé : une personne déjà liée à une autre fiche, opposée (`opposition_at` ou `opt_out`), ou dont le contact porte une autre clé reste intacte (raisons `personne_liee_ailleurs`, `personne_opposee`, `person_key_divergente` dans le journal).
- Drapeaux `personnes_enabled` et `demandes_personne_enabled` fermés : aucune requête sur `personnes`, aucun verrou. Le solde des demandes exige `demandes_personne_enabled`.
- Verrou de transaction par personne pris avant `rapprocher()`, clés triées (pas d'interblocage entre deux dossiers).
- Le chemin d'arbitrage humain (`appliquerApresArbitrage`) ne lie rien (coupé, voir le plan §5).
