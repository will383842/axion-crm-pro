# D1-L3 — commandes des boîtes (secrets jamais en argument)

Cahier : `docs/envoi/lots/D1-D2-cahier.md` (PR #617), sections 0 et 3. Préalable : D1-L1 (#620, table `envoi_boites_acces_imap`).

- `envoi:boite-creer {workspace} {adresse} {hote_smtp} {port_smtp} {chiffrement}` : identifiant puis mot de passe SMTP en invite
  masquée ou sur l'entrée standard ; `DepotBoites::creer` (garde anti-SSRF `GardeHoteSmtp`) ; affiche l'UUID de la boîte.
- `envoi:boite-secret {workspace} {boite} {hote_imap} {--retirer}` : identifiant puis mot de passe IMAP (rien avec `--retirer`) ;
  hôte pris dans la liste fermée `HotesImapBoites::LISTE` (identique au CHECK de la table) ; port 993 et `ssl` imposés.
- `envoi:boite-reprendre {workspace} {boite}` : `DepotBoites::reactiverSuspensionManuelle` ; une pause automatique ou de frein
  n'est pas levée (code 1).
- `DepotAccesImap` : `poser`, `retirer` (ligne inactive sans secret), `decrire` (ne déchiffre pas), `parametres` (seul endroit
  qui déchiffre ; échec = « accès IMAP illisible »). La dernière ligne fait foi. Aucun UPDATE ni DELETE.

Aucune connexion IMAP ou SMTP, aucun drapeau, aucune configuration, aucune route. Sortie, journaux et exceptions sans secret.
Mise en service : le responsable du projet pose les accès sur le serveur avec `envoi:boite-secret` (jamais dans un ticket).
