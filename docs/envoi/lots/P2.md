# P2-A — inscriptions typées (migration SEULE et INERTE)

## Fait
Trois migrations ADDITIVES (aucune ligne créée, aucune donnée touchée, `down()` inerte, `up()` rejouable) et des tests. Aucun fichier de `app/` ; aucun drapeau (`ENVOI_REEL_ACTIF`, `config/envoi.php` : inchangés) ; aucun interrupteur posé (l'absence de ligne = éteint). L'index unique « une inscription active par adresse » est P2-B.

1. `2026_12_05_000100_envoi_inscriptions_population.php` (transaction, `lock_timeout = 5s`) — colonnes `population` (défaut constant `entreprises`, sans réécriture) et `personne_id` ; CHECK `..._population_valeur` et `..._population_coherence` (NOT VALID puis VALIDATE) ; ensuite seulement `contact_id` et `entreprise_id` deviennent nullables. Déclencheur `envoi_inscriptions_population_garde` (sans SECURITY DEFINER, `search_path = pg_catalog, public, pg_temp`) : colonnes figées ; « personnes » refusée sauf réglage `envoi.population_personnes` = `true` visible dans l'espace.
2. `2026_12_05_000110_envoi_inscriptions_personne_index.php` (hors transaction) — index unique partiel `envoi_inscriptions_personne_unique (workspace_id, sequence_id, personne_id) WHERE personne_id IS NOT NULL` ; un index invalide de CE nom est supprimé (lui seul) puis recréé.
3. `2026_12_05_000120_envoi_reglages_interrupteur_population.php` — déclencheur `envoi_reglages_interrupteur_population` : la clé ne se pose (INSERT, UPDATE, renommage) que par un membre du rôle propriétaire de la table ; valeur `true`/`false`.

## Tests
`tests/Feature/Envoi/SchemaInscriptionsPopulationTest.php` (préfixe `ipp`) : structure, ancien chemin (`Inscriptions::inscrire`), CHECK, interrupteur, contexte d'espace absent, table temporaire homonyme, colonnes figées, garde de la clé, inertie + test de source (aucune occurrence de la clé dans `app/`), rejouabilité, unicité par personne. Sécurité rejouée sous le rôle applicatif (`SET LOCAL ROLE` + `WorkspaceContext`) ET sous le propriétaire. NR-17 : trois lignes dans `NR17_RETOUR_INERTE_VOULU`.

Mutations prouvées (chacune fait rougir le test prévu) : `ouvert IS NOT TRUE` → `NOT FOUND` (interrupteur) ; `pg_temp` retiré (structure) ; branche « personnes » retirée (interrupteur, table temporaire) ; gel retiré (figé) ; garde de la clé retirée (garde de la clé).

## Limite honnête
Le propriétaire des bases de test (local et CI) est SUPERUTILISATEUR : il contourne la RLS. Le cas « propriétaire sans contexte d'espace = refus » n'est donc vérifié que si ce rôle est soumis à la RLS (sinon le test vérifie le rôle applicatif sans contexte). Même limite pour la mutation « `row_security = off` retiré », qui concerne P2-B.

## Déploiement
Le code ne change pas (migrations seules) : la fenêtre « nouveau code sur ancien schéma » est sans effet. L'ancien code écrit `population` par défaut `entreprises`, CHECK satisfait.
