# R09 — Campagnes : suivi et gestes (point a)

Branche `feat/r09-campagnes-suivi` (depuis `origin/main`, avec `feat/r08-modele-campagne` et `feat/r08b-modeles` fusionnées). Aucune PR ouverte, aucun workflow lancé, tous les commits en `[skip ci]`.

## Fait
- **Lecture** (`users.manage`) : `GET /envoi/campagnes` (filtre `statut`, `recherche`, pagination, comptes par statut), `/calendrier` (semaine en cours par défaut, 62 jours au plus), `/{id}` (fiche), `/{id}/destinataires` (vide tant que `sequence_id` est nul, donc toujours).
- **Gestes** (`workspaces.manage`, owner seul) : `POST /{id}/pause`, `/reprise`, `/terminer`, `/dupliquer`, `/date`.
  - `reprise` : 409 `frein_arret_general` si l'arrêt général est armé, 409 `frein_pause_automatique` si une pause automatique est active.
  - `terminer` : irréversible (aucune sortie de `terminee` dans la matrice, base comprise).
  - `dupliquer` : toujours un **brouillon** (version 1, sans séquence, sans date) ; `garder_cible=false` met une cible neutre « À choisir » ; `garder_messages=false` vide la saisie.
  - `date` : campagne `programmee` seulement, strictement dans le futur et au plus 90 jours (`envoi.campagne_date_fenetre_jours`).
  - Tous les gestes passent sous un verrou consultatif de l'espace (`envoi:campagnes:<espace>`), chacun journalisé (journal des transitions, ou journal des commandes pour la date et la copie).
  - `Idempotency-Key` (8 à 100 caractères) : un geste rejoué avec la même clé ne refait rien et ne journalise qu'une fois ; sans clé, le serveur en dérive une (campagne, geste, version).
- **Contrat** : `campagnes.yaml` déclare son propre schéma `CampagneSuivi` (sans `ab_objet`, `etapes` 1 à 3, `+ envoi_ferme`, `+ version`) ; `commun.yaml` n'est pas touché. `.d.ts` régénérés, écran et handlers de démo alignés.
- **Migration** `2026_12_02_000090_envoi_campagnes_date.php` : `ADD COLUMN IF NOT EXISTS envoi_prevu_le TIMESTAMPTZ NULL` + droit UPDATE du rôle applicatif sur cette colonne seulement (toujours aucun droit sur `sequence_id`). `down()` inerte.

## Risques
- Le verrou de l'espace est propre aux campagnes ; je n'ai pas trouvé de verrou « des freins » à réutiliser (les freins ne posent aucun verrou consultatif). Un frein posé pendant une reprise est lu juste avant la transition, pas verrouillé.
- La « fenêtre » de la date est une fenêtre en jours (90) : si le plan visait aussi les heures d'envoi, c'est à préciser.
- Taille : le lot dépasse 400 lignes (tests compris) ; il aurait dû être livré en deux PR (lecture, gestes). Pas de PR ouverte (consigne).

## Points notés pour relecture
- Aucune route n'appelle `ServeurEnvoi`, `AdaptateurSmtp`, `Sequenceur` ni `PasserelleLocale` ; aucune URI ne contient `temoin`, `tout-arreter`, `reprendre`, `armer` (la route s'appelle `reprise`).
- `sequence_id` n'est jamais écrit ; `pause` / `terminer` / `reprise` donnent donc 409 au palier 0 sur toute campagne réelle (aucune n'est `en_cours`).
- Le test de reprise utilise `envoi:lever-pause` et `armerToutArreter` de test uniquement.
