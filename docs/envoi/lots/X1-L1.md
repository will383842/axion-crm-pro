# X1-L1 — schéma qui relie une campagne validée à sa séquence

## Fait
Quatre migrations ADDITIVES (aucun DROP de colonne ou de table, aucune ligne touchée, jamais de SET NULL / CASCADE, `down()` inerte) et des tests. Aucun code applicatif (`DepotCampagnes`, `Sequenceur`… : lot suivant). `ENVOI_REEL_ACTIF` et les drapeaux : inchangés.

1. `2026_12_04_000010_envoi_sequences_campagne.php` — `envoi_sequences.campagne_id` (NULL), clé étrangère composite `envoi_sequences_campagne_fk` (NOT VALID puis VALIDATE), index unique partiel `envoi_sequences_campagne_unique` (une séquence par campagne = clé de reprise). Déclencheurs (tous rôles, `SET search_path = pg_catalog, public`) :
   - `envoi_sequences_garde_campagne_insert` : la campagne (lue `FOR SHARE`) doit être `programmee`, de l'espace, sans `sequence_id` ;
   - `envoi_sequences_garde_campagne` : `campagne_id` figé (y compris NULL → valeur) ; fenêtres figées si la séquence est née d'une campagne ;
   - `envoi_sequences_nee_en_pause` : geste `pause`, auteur `campagne:naissance`, `cree_le = clock_timestamp()` ;
   - `envoi_sequence_etapes_figees` : étapes (INSERT/UPDATE/DELETE) refusées dès qu'une campagne pointe sur la séquence.
2. `2026_12_04_000020_envoi_campagnes_materialisations.php` — table `envoi_campagnes_materialisations` (RLS forcée, FK composites, CHECK sur état, curseur, compteurs numériques ≤ 2048 octets, motif en liste fermée). Garde : `campagne_id`, `workspace_id`, `cree_le` figés ; `sequence_id` NULL → valeur seulement ; curseur jamais décroissant ; `en_cours` → `terminee`|`bloquee` seulement. DELETE/TRUNCATE refusés. Droits : SELECT, INSERT, UPDATE sur sept colonnes.
3. `2026_12_04_000030_envoi_campagnes_lien_sequence.php` — compte les `sequence_id` orphelins et **s'arrête avec leur nombre** (ne met jamais la colonne à NULL) ; FK `envoi_campagnes_sequence_fk` (NO ACTION) ; `envoi_campagnes_garde()` : garde toutes les règles de R08 et ajoute (a) le lien unique (NULL → valeur, `programmee` avant et après, séquence de la même campagne et du même espace lue `FOR KEY SHARE`, nombre d'étapes = `nb_etapes`) et (b) cible, boîtes, `nb_etapes`, saisie figées + `programmee → a_valider` refusé une fois reliée ; `envoi_campagnes_pause_sequence` (pause/fin/arrêt → geste `pause`, auteur `campagne:<statut>`) ; `envoi_sequences_gestes_reprise_campagne` (reprise acceptée seulement si campagne `en_cours` ET matérialisation `terminee`) ; `GRANT UPDATE (sequence_id)` (jamais INSERT).
4. `2026_12_04_000040_envoi_inscriptions_contact_actif_index.php` — `$withinTransaction = false` ; index invalide supprimé (lui seul, `DROP INDEX CONCURRENTLY`) puis `CREATE INDEX CONCURRENTLY IF NOT EXISTS idx_envoi_inscriptions_contact_actif`. Dans une transaction (tests) : index simple, comme les autres migrations du dépôt.

Numéros réservés après vérification : aucune migration existante ni PR ouverte n'utilise `2026_12_04_*`.

## Écart au plan (renforcement, à valider)
`envoi_sequence_etapes_figees` prend d'abord un verrou `FOR UPDATE` sur la ligne de la séquence : une liaison (`FOR KEY SHARE`) et une écriture d'étape se sérialisent, donc un ajout d'étape concurrent ne peut pas passer entre le comptage et la pose du lien.

## Preuve de mutation
Chaque garde a été cassée dans la migration, le test visé a rougi, puis la migration a été restaurée :

| Garde cassée | Test qui rougit |
|---|---|
| lien : statut `programmee` avant/après | liaison refusée hors du statut programmee |
| lien : nombre d'étapes = `nb_etapes` | liaison refusée si le nombre d'étapes diffère |
| reliée : `programmee → a_valider` refusé | campagne reliée : programmee -> a_valider refusé… |
| reprise : matérialisation `terminee` exigée | reprise refusée tant que la campagne n'est pas en_cours ET la matérialisation terminee |
| étapes figées (EXISTS) | séquence : campagne_id et fenêtres figés ; étapes figées… |
| `campagne_id` figé | idem |
| naissance : `clock_timestamp()` → `now()` | séquence née en pause (`cree_le > now()`) |
| pause de la campagne : `clock_timestamp()` → `now()` | le geste pause est ordonné après la naissance |
| curseur qui ne décroît pas | matérialisation : transitions, curseur… |
| déclencheur DELETE de la matérialisation | matérialisation : DELETE et TRUNCATE refusés |

Limite honnête : la ligne « retrait / second lien » de `envoi_campagnes_garde()` est redondante avec les autres gardes (une séquence d'une autre campagne ou `NULL` échoue de toute façon à la recherche de la séquence) ; la casser seule ne fait rougir aucun test. Elle est gardée en défense en profondeur, comme le plan l'exige.

## Risques / reste
- Deux conteneurs (api / scheduler) : migrations additives, l'ancien code ignore la colonne et la table ; l'ancien code ne pose jamais `sequence_id` (aucun droit) donc la nouvelle FK ne le gêne pas.
- `DepotCampagnes::TRANSITIONS` doit refuser `programmee → a_valider` pour une campagne reliée (lot suivant).
- Si des `sequence_id` orphelins existent en production, la migration 3 s'arrête avec leur nombre : décision humaine (aucune correction automatique).
