# X11-B — rotation entre boîtes, boîte figée par inscription

Cahier : FINI-cahier.md (PR #680), section X11-B. Dépend de FINI-M0B (`envoi_inscriptions.boite_id`) et de #677 (fusionnée).

- `ChoixBoite::pour` : boîte figée ⇒ elle seule (inactive ⇒ `EnvoiRefuse` ATTENTE, report sans compteur) ; sinon boîtes actives du
  domaine de l'expédition, restreintes aux `boites` de la campagne si elle en liste, tri (envoyés du jour, `cree_le`, `id`), pose par
  `UPDATE … WHERE boite_id IS NULL` (l'autre ouvrier relit). Aucune boîte ⇒ ATTENTE.
- `Sequenceur` : l'expéditeur (From et `MessageAEnvoyer`) vient de `ChoixBoite`, choisi AVANT la réservation (rien de réservé en cas
  de report). Paramètre `choixBoite` optionnel : absent (tests, ouvriers existants) = expéditeur fixe d'origine ; `sequenceurPour`
  le branche toujours.
- `SourceExpeditionDb::boitesActivesDuDomaine`.
- `GardeChauffe` inchangée (quota par boîte). Aucun envoi réel (`ENVOI_REEL_ACTIF` non touché).

Écart assumé : le test à deux processus réels n'est pas fourni (il demanderait un nouvel ouvrier hors fichiers autorisés) ; la course est
simulée par une lecture périmée de l'inscription (mutation : retirer `WHERE boite_id IS NULL` ⇒ le test « course » devient rouge ou le
déclencheur de figement lève).

Correctif de relecture : test « câblage Sequenceur » (2 boîtes, `a` déjà à 3 envoyés, inscription sans boîte ⇒ expéditeur composé, `boite_id`
figé et message reçu = `b@…`). Mutation locale (restaurée, rien poussé) : `Sequenceur` remis sur `$this->expedition->expediteur` ⇒ ce test
rougit. Tri : les envoyés du jour sont calculés une fois par boîte (plus de requêtes dans `usort`).

Preuve : rouge = PR de preuve #710 (tests seuls) ; vert = CI de la PR du lot. Pas de PostgreSQL dans le bac à sable.
