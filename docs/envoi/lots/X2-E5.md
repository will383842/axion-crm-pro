# Lot X2 vague 1 — E5 : code SMTP du refus définitif

## Problème
Le code SMTP d'un refus définitif doit finir dans `envoi_tentatives.code_smtp`. Il manquait dans 4 cas.

## Correctif
- `ServeurEnvoiKumo` : la ligne du registre reçoit une clé **facultative** `code`.
  Elle est écrite au 5xx reçu à l'injection, relue dans le cas `echec` (rejeu) et dans `refuser()`
  (refus lu par interrogation) ; sans code connu, le code reste `null` (jamais inventé).
  `RegistreInjections` / `RegistreMemoire` : seul le type de tableau documenté change (`code?: int`), les implémentations existantes restent compatibles.
- `AdaptateurSmtp` : `classer()` passe `$code` à `RefusDefinitifServeur` ; le rejeu d'une clé en `echec` relit `code_smtp` dans `envoi_injections_smtp`
  (valeur hors 200..599 → `null`, jamais d'exception).

## Hors périmètre
`AdaptateurSmtp::classer` (un 5xx de bannière donne un echec terminal) : autre lot. Aucun drapeau touché, aucune migration.
