# Envoi P0 — relève IMAP (lot L6)

## Principes
- **Boîte en lecture seule, prouvée sur le fil** : `EXAMINE` (jamais `SELECT`), `UID SEARCH`, `UID FETCH (RFC822.SIZE INTERNALDATE)` puis `UID FETCH (UID BODY.PEEK[])` (jamais `RFC822`, `BODY[]` sans PEEK, `STORE`, `COPY`, `MOVE`, `EXPUNGE`, `APPEND`). Le message est construit en mémoire par `Message::fromString`. Le test `ReleveImapAuditTest` enregistre les commandes envoyées à un faux serveur IMAP (flux PHP, aucun réseau) et prouve l'absence de ces commandes.
- **Panne ≠ illisible** : une panne (réseau, IMAP) est une exception technique ; le message n'est jamais classé « écarté » et le curseur n'avance pas (relu au passage suivant). Seul un message au MIME réellement illisible est écarté (« à rattacher », sans effet).
- Seuls des empreintes, la classe du retour et des identifiants techniques sont écrits (`envoi_evenements`, ajout seul). `id_injection` est un UUID contrôlé à l'insertion comme une clé étrangère vers `envoi_injections_smtp` (même espace ; un déclencheur plutôt qu'une FK, qui bloquerait le retour arrière de L4 — NR-17).
- **Isolement par message** : un message piégé ou dont l'arrêt est inapplicable (`RetourInapplicable`) devient « à rattacher » **sans effet** ; la boîte continue. Une **erreur propre à un message** (code non nul de `crm:campagne:retours`, exception base) est journalisée, comptée dans `envoi_echecs_releve` (ajout seul), n'empêche pas de traiter les suivants ; le curseur reste avant le premier échec ; `ReleveIncomplete` est levée en fin de passage. Après 3 échecs (`MAX_TENTATIVES`), le message est mis à l'écart (« à rattacher », revue humaine) — **un STOP dans ce cas dépend donc de la revue humaine (L8)**.
- **Freins L7** : chaque retour qui compte (désinscription, plainte, rebond dur, rebond mou) est transmis à `AppliquerRetour` (`RecepteurRetoursFreins`) en plus de `crm:campagne:retours` (`RecepteurRetoursEnChaine`). Identifiant d'événement = empreinte du message (stable : un rebond n'est compté qu'une fois, même après renumérotation des UID).
- **Rebonds** : un rebond dur sans `Final-Recipient`, ou dont il diffère de l'adresse d'origine, est « douteux » (à rattacher). Un `5.7.x` (politique, réputation, « rejected as spam ») n'est **pas** un rebond d'adresse : classé sans effet (`auto_reponse`), le code est conservé dans `code_dsn`.
- **Analyse prudente** : un échec de regex (UTF-8 invalide, limite PCRE) n'est jamais une chaîne vide : le message est traité comme un STOP, jamais comme « réponse humaine ». STOP prime sur « hostile » ; `Precedence: bulk/junk` n'est plus qu'un indice faible, après la recherche d'un STOP. « spam », « plainte », « signaler », « illegal » seuls ne déclenchent plus « hostile ».
- Limites : au plus 200 UID bruts par passage (`lotPlein` suit les UID bruts) ; `RFC822.SIZE` lu d'abord, au-delà de 256 Kio le message est écarté sans être téléchargé ; aucune pièce jointe enregistrée ; chiffrement `ssl`/`tls`/`starttls` seulement, certificat toujours vérifié.
- Rattrapage après panne : fenêtre de 30 jours fondée sur INTERNALDATE, **paginée sur les UID bruts jusqu'à la fin réelle de la boîte** (un lot entièrement filtré par la date n'arrête pas la boucle).
- Tables d'ajout seul : `envoi_evenements`, `envoi_rattachements` (rattachement ULTÉRIEUR d'un événement « à rattacher » : on ajoute une ligne, l'événement ne change jamais), `envoi_echecs_releve`, `envoi_messages_envoyes` (registre des Message-ID envoyés ; `RegistreMessagesEnvoyesDb`). Le lot d'injection doit encore l'alimenter.

## ⚠ File « à rattacher » : revue humaine obligatoire avant mise en service (lot L8)
Un message « à rattacher » n'a **aucun effet**. Une opposition (STOP, plainte) qui s'y trouve n'est donc **pas** appliquée tant qu'une personne ne l'a pas traitée. Avant toute mise en service, le lot L8 doit fournir : une vue de la file (`statut = 'a_rattacher'`, `classe` en `desinscription`/`hostile`), un délai de traitement tenu, et une alerte si la file dépasse un seuil. Sans ce circuit, ne pas envoyer.

## Dépendance `webklex/php-imap` 6.2.0
Version **exacte** épinglée (pas de `^`). Risque : un seul mainteneur, environ 18 mois sans activité. `composer audit` (job `composer-audit`, bloquant) couvre les avis connus. Plan de sortie : tout passe par l'interface `LecteurBoite` ; remplacer `LecteurBoiteWebklex` n'affecte ni la classification, ni le rattachement, ni les arrêts.
